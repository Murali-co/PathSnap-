# PathSnap web frontend

React + Vite + TypeScript frontend for the existing PathSnap FastAPI API. The
development server proxies `/api/*` to the backend, so browser requests remain
same-origin and do not require changing the backend's CORS settings.

## Windows setup

From this directory, install dependencies and start the frontend:

```powershell
npm ci
$env:VITE_API_BASE_URL = "http://localhost:8000"
npm run dev
```

Open the local URL printed by Vite (normally `http://localhost:5173`). If the
backend is on another laptop, set the proxy target to its reachable LAN URL,
for example `http://192.168.1.20:8000`, in `.env.local` or the environment
before running `npm run dev`. The
backend must be listening on a network interface and its port must be reachable.

## Checks

```powershell
npm run typecheck
npm run build
```

The frontend displays public input roads, GPS, classifier routes and actual decoded road geometry returned by the backend, plus available aggregate reference scores. Route pieces remain separate across gaps. Missing or invalid GPS rows are safely ignored when plotting; the API preserves observation-level statuses.

The default vector map needs no online tiles. You can enable the optional OpenStreetMap basemap; it requires internet and provider attribution. The existing visual theme requests optional Google Fonts, with local sans-serif fallbacks. This browser frontend is separate from the Python Streamlit frontend.

For a production deployment, configure the static host/reverse proxy to forward `/api/*` to Laptop 1. Vite's proxy applies to development. Production files are generated by `npm run build` in `dist/`; do not commit dependency folders, build output, ZIPs or `.env.local`.

Validation: run `npm run typecheck` and `npm run build`. Browser integration evidence is recorded separately when executed; a build alone does not prove a physical two-laptop connection.
